Tailscale-OHOS：VPN 后台保活与蜂窝网直连修复

项目 /Volumes/Doc/dev/Tailscale-OHOS　·　2026-09-18　·　 依据：Tailscaler 已验证实现 + llmwiki 两个 concept 页
结论

两项问题均已修复并通过构建验证：后台保活按华为官方 VPN 保活方案改为 dataTransfer 长时任务 并由 EntryAbility 持有；蜂窝直连补齐 netmon 鸿蒙适配（宿主上报默认网卡）并固定 UDP 端口 41641。 修复前这两条链路在本项目内完全不存在——不是配置偏差，而是功能缺失。

构建结果：BUILD SUCCESSFUL，产出 HAP 与 AArch64 Go 库。 真机验收未做，原因与命令见第 5 节。

2. 后台保活：改了什么

  • entry/src/main/module.json5：backgroundModes → ["dataTransfer"]； KEEP_BACKGROUND_RUNNING 补 reason + usedScene(when: always)。
  • 新增字符串资源 background_running_reason（base 英文 / zh_CN 中文）。
  • services/VpnBackgroundTaskManager.ets：重写为模块级单例 vpnBackgroundTaskManager，只接受 UIAbilityContext；DATA_TRANSFER 模式； 每 4 分钟 updateBackgroundRunning 刷新进度；监听 continuousTaskCancel/Suspend/Active；被取消后同一会话内不再重复申请（合规）。
  • entryability/EntryAbility.ets：onCreate 注册监听并绑定上下文； onBackground 申请任务；onForeground 在无会话时取消。
  • vpnextensionability/TailscaleVpnExtensionAbility.ets：移除 4 处后台任务调用—— 该进程没有 UIAbility，不可能持有长时任务，它只负责写状态文件。
  • components/BridgeStatus.ets：vpnStatus 绑定 @Watch('handleVpnStatusChanged')，前台完成连接也能立刻武装保活任务。

对参考实现的两处修正

移植时发现 Tailscaler 侧有两处实现在运行中不会生效，本项目已修正： Tailscaler 待修

① handleVpnStatusChanged 漏绑 @Watch

方法定义了，但 vpnStatus 上没有 @Watch 装饰器，属死代码， 前台连接→切后台这条路径实际不生效。

② scheduleSessionProbe 从未被调用

有界探测（24×500ms）写好了却没有调用点， 「点连接后立刻切后台」的竞态没有覆盖。本项目在 onBackground 接上。

3. 蜂窝网直连：改了什么

层改动
上游 net/netmon 新增 harmony_os_openharmony.go / harmony_os_other.go：用 build tag 提供编译期常量 isHarmonyOS。不能用 runtime.GOOS == "openharmony"——OpenHarmony 工具链下该值实为 "linux"，判断恒假且不报错。
上游 net/netmon/interfaces_linux.go UpdateLastKnownDefaultRouteInterface（宿主上报）+ fallbackDefaultRoute + guessHarmonyDefaultRouteInterface；defaultRoute() 改为 /proc/net/route → netlink → 上述回退 链。
上游 net/netmon/state.go isHarmonyProblematicInterface：过滤 IMS rmnet_ims*、运营商 anchor ancormnet*、vpn-tun 与各类虚拟接口。
上游 tsnet/tsnet.go 新增 NotifyNetworkChange：先 mon.InjectEvent() 等 netmon 重新采样， 再无条件 DebugRebind()。
Go 桥接 backend.go tsnet.Server 加 Port: 41641；新增 setDefaultRouteInterface()； networkChanged() 从 client.DebugAction("rebind") 改走 NotifyNetworkChange 并附带 NetworkDiagnostics。
NAPI backendSetDefaultRouteInterface：napi_init.cpp + index.d.ts + main.go 导出 TSBackendSetDefaultRouteInterface。
ArkTS 上报 networkPropertiesCallback 取 connectionProperties.interfaceName， 经 isPhysicalNetworkInterface() 白名单过滤后缓存；在 rebindForNetworkChange 里先推送网卡名、再触发网络变化通知。
补丁同步 patches/tailscale-ohos.patch 重新生成（840 行 / 10 文件）。 构建脚本用 git apply --reverse --check 判定，patch 与源码不一致会直接在打补丁阶段失败。
为什么顺序不能反

UpdateLastKnownDefaultRouteInterface 只写一个变量。netmon 的缓存状态是在 InjectEvent() 触发重新采样时才重算的；先推送、后通知，magicsock 在 rebind 时才读得到 这个网卡名。反过来的话名字写进去了但没有一次重采样把它带进缓存。

5. 未完成：真机验收

阻塞项　签名材料缺失。本项目 certs/ 只有 3 个 release 证书， 没有 p12 私钥与 p7b profile；设备上现有的两个 debug profile 分别绑定 com.penglei.tailscaler 与 com.penglei.hermex，都不匹配本项目包名 io.github.tailscaleohos，因此无法命令行签名安装。

需在 DevEco Studio 里为本包名申请 debug profile（或导入已有签名配置到 build-profile.json5 的 signingConfigs）后，按下表验收：

# 0) 安装（签名后）
hdc install -r entry/build/default/outputs/default/entry-default-signed.hap

# 1) 声明是否生效：期望 backgroundModes 位值为 1（= DATA_TRANSFER）
hdc shell bm dump -n io.github.tailscaleohos | grep -i backgroundModes

# 2) 连接后回桌面：通知栏应出现「正在运行数据传输任务」
#    长跑期间任务保持/刷新日志：
hdc shell hilog | grep VpnBackgroundTask

# 3) 蜂窝直连：期望 defIf 由 "" 变为 rmnet0、端点出现 stun4localport、路径变 direct
hdc shell hilog | grep -E "network change|network_default_route|Rebind"

真机上「连接后锁屏 8–24 小时不掉线」与「Wi-Fi ↔ 蜂窝切换后延迟」两项仍需实测； 本报告的结论边界止于构建与静态产物验证。
